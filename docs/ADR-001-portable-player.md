# ADR-001：跨平台播放、本地资料库与免扩展登录

日期：2026-11-12。

## 目标与现状

原程序通过 Windows Media Foundation 播放、WinHTTP 联网、WIC 解码封面、WebView2 登录，队列与账号歌单承担全部曲目管理。目标是默认展示发现页，支持 Linux、独立本地收藏与在线歌单快照，并在系统默认浏览器完成登录。

## 决策与边界

- `audio::Player` 独占音频引擎和声音资源，由 UI 线程调用；miniaudio 实现在单独编译单元。`prepare_file` 在后台识别 AAC/m4a，通过 argv 调用系统 FFmpeg；不经过 shell。MP3、FLAC、WAV 直接解码。
- `platform.hpp` 处理 UTF-8 文件路径、用户目录、进程调用和默认浏览器。业务适配器统一使用 `net` 接口：Windows 保留 WinHTTP，Linux 使用 libcurl。Linux 封面通过 stb_image 解码；现有 Windows WIC 路径保留。
- 本地资料库只含曲目元数据、全部源候选和可选远程歌单引用。UI 线程独占资料库，后台任务返回完整快照；先写临时文件再替换，成功后才发布到 UI。损坏数据和刷新失败不会覆盖已保存内容。
- 登录模块拥有可取消、可回收的后台线程。系统默认 Chromium 浏览器在独立临时 profile 中打开真实官网，扫码、密码与验证码均由官网实现；播放器通过仅本机可达的 CDP 连接取得对应音乐网站 Cookie，并交回业务模块保存、刷新歌单和请求宿主激活。浏览器扩展和内嵌 WebView 均不参与流程。
- 本机调试端口由浏览器随机分配，只连接自己启动的独立会话。Cookie 查询限于对应官网 URL，并额外检查域名和字段；不访问日常浏览器数据库。备用手动 Cookie 导入仍使用回环地址、随机令牌、Host/Origin/内容类型及长度检查，并向音乐网站验证，不作为正常 UI 路径。
- 持有的后台工作在窗口销毁前停止并回收；后台对 UI 状态的修改通过主线程消息队列处理。缓存按进程隔离，避免同时运行的新旧播放器互相删除文件。
- 播放条收藏使用独立的当前曲目快照，切换列表或搜索后仍收藏正在播放的歌曲。复用本地收藏持久化与状态显示。

## 替代方案与代价

不继续使用 Media Foundation / WebView2，是因为它们无法覆盖 Linux。没有引入完整播放器框架；单头文件 miniaudio 保持 API 小且跨平台，但 AAC 需要系统 FFmpeg，转码会增加启动时间和临时空间。

没有采用浏览器扩展：安装和配置增加用户负担。旧版自写扫码页只验证了二维码生成与等待，用户手机确认后仍无法完成登录，因此改用真实官网的完整验证流程。代价是自动回传目前要求默认浏览器为受识别的 Chromium 浏览器，并允许本机调试连接；Firefox 等其他内核不在本次自动回传范围。

本地歌单保存快照而非音频，使离线曲目浏览、收藏和重启恢复独立于账号。播放仍受网络和平台权限影响；QQ 自建歌单需保存 owner + dirid，公共歌单使用 disstid。

Windows 字体跟随系统消息字体，保留现有 GDI 灰度抗锯齿，避免改变整个文字渲染架构；不会达到 DirectWrite / ClearType 的像素一致效果。

## 验证与剩余风险

- Windows MSVC 和 MinGW Release 构建、资料库/凭据回归、本机备用导入 HTTP 边界检查、独立业务测试。
- Windows 真实设备验证 WAV、MP3、FLAC、AAC/m4a 播放、暂停、定位、恢复和自然结束。
- 隔离用户配置验证发现页、本地收藏增删、保存命名快照、保存真实网易云榜单。
- 真实 Chrome 离线注入假凭据，覆盖两家 Cookie 回传、错误域名/路径排除、关闭旧标签后继续等待、QQ 缺失密钥、取消、清除登录态、返回请求及临时 profile 清理。此测试不等同于手机确认登录。
- Linux CI 已通过编译、离线业务回归与 Xvfb 窗口冒烟测试；真实音频设备和 Linux 手机扫码登录尚未实机验证。Windows 手机确认后的完整账号登录已由用户确认可用。

接口稳定性、明文保存在本机配置的 Cookie、AAC 对 FFmpeg 的依赖是明确保留的限制。没有改动仓库提交历史。

## 代码审查结果

已检查模块边界、退出时的线程生命周期、文件替换、登录路由和构建依赖。审查中修复了三处问题：HTTP 分片请求在 100ms 后被误判失败、取消登录与扫码成功同时发生时仍可能发布凭据、切换列表后播放条收藏可能找不到当前歌曲。HTTP 分片增加了回归检查；收藏增删与切换列表通过隔离配置的实际窗口操作验证。

旧自写扫码协议、二维码脚本和对应模拟状态测试已移除，改由真实浏览器 Cookie 回传回归覆盖当前路径；原 WebView2 和扩展代码继续移除。MinGW 仍有标准库 `wstring_convert` 弃用警告；本次未改动无关的标签转换代码。

尚缺 Linux 真实音频设备和 Linux 手机确认后的完整登录测试，因此不将这些项目标为验证通过。

## 2026-11-12 补充：数据管理、扫码回传与三文件应用结构

遵循用户指定的粒度，应用只分为 `main.cpp`、`business.hpp`、`ui.hpp`。入口管理窗口与帧循环；业务持有后台任务、账号和播放设备，向 UI 提供只读快照和动作接口；UI 只处理绘制和输入。两个实现头由入口单一包含，保留 aino 的单编译单元约定，不额外建立模型、控制器、配置和视图等小文件。

设置增加独立的数据与缓存视图和四类确认清除。配置及队列使用临时文件替换；清除登录信息会取消会话并拒绝过时的账号刷新结果，清空列表会使旧搜索和歌单请求失效，清空资料库会使旧导入失效。缓存清理限定于播放器生成的文件名，跳过链接、其他活动进程和正在播放/写入的文件，不递归清理下载目录。

此前尝试对齐网易云扫码入口和 POST 轮询参数，但用户仍报告手机确认后页面一直等待。该方案现已被官网浏览器登录替换，不再把生成二维码和等待状态当作完整登录验证。成功状态发布与凭据发布仍处于同一互斥区，清除账号可取消当前尝试并阻止旧结果重新发布。

业务回归独立编译，不依赖 aino：覆盖默认发现、队列去重与换源、收藏和命名快照、退出账号及持久化、保留其他设置、缓存清理保留下载，以及登录返回的宿主回调。隔离配置与临时目录的实际窗口验证四类清除的取消/确认操作；不会修改真实账号数据。官网登录回传由 `browser_login_test.py` 驱动真实隔离浏览器验证。


## 2026-11-12 补充：直接进入官网

登录职责仍在既有 `login.cpp/.h`，不新增应用模块，入口、业务和 UI 继续保持三个文件。浏览器直接访问网易云或 QQ 音乐官网，用户点击官网登录入口。启动使用原生进程参数，不经过 shell；临时 profile 与播放器其他数据分开，成功、取消、窗口关闭或超时后回收。

Windows 使用独立 Job 约束本次浏览器及其子进程，先请求正常退出再兜底回收；清理只针对生成的 profile 路径。Chromium 组件路径可能超出 MAX_PATH，清理时将分隔符规范化并使用扩展路径。MinGW 标准库清理长路径时曾出现忙循环，现使用有深度上限、不跟随重解析点的原生 Windows 目录枚举与删除。WebSocket 检查握手响应、限制消息大小和请求期限，标签被关闭时重新绑定存活页面。没有访问浏览器日常用户目录，也没有要求安装扩展。

回归增加真实 Chromium 进程的两家假 Cookie 回传和取消/清除场景；同时保留 HTTP 备用导入边界和独立业务测试。Linux 进程与默认浏览器解析代码已实现；CI 验证构建与窗口启动，手机确认登录已由 Windows 用户反馈可用，Linux 完整账号流程仍需实机验证。


## 2026-11-12 补充：发布、自动更新与交互恢复

仓库按用户授权设为公开，播放器对固定的 GitHub Releases API 发起无凭据的后台请求。应用版本来自 CMake 项目版本，按数字三元组比较正式版，避免字符串比较导致 `1.10` 排在 `1.9` 之前。只接受本仓库的 HTTPS 发布页和安装包链接；草稿、预发布、网络错误及请求限流不会误报为最新版。UI 通过只读更新快照显示状态，动作和网络请求继续位于 business.hpp，不新增应用模块。

发布通过标签触发双平台 CI。Windows 输出原生 x64 exe；Ubuntu 22.04 输出带依赖声明及桌面入口的 amd64 deb，安装并执行 Xvfb 冒烟后才允许发布。首次版本为 v0.1.0。实际手机登录已由用户反馈可用，自动化登录回归仍使用隔离 profile 和假 Cookie。

交互缺陷定位到 aino 的 active 控件只能由原控件在松手时释放；刷新、布局变化、滚动裁剪或切页使原控件不再绘制时，active 会永远非零，阻止普通按钮认领后续点击。歌词直接读取鼠标事件，因此仍可交互。修复在全部普通及延迟控件处理完输入后统一清除已松手的 active，同时在 Windows 失焦/丢失捕获和 X11 FocusOut 时取消按下状态。回归直接覆盖控件消失、缺失鼠标松开事件，以及正常拖动和后续点击。


## 2026-11-12 补充：文件夹歌单、多源适配与浏览边界

应用继续只用入口、业务、UI 三个文件；扩展既有 library/sources/platform/audio 模块，不引入新的应用分层小文件。`gdmusic/include` 只作为协议与纯算法参考，其 WinHTTP 专属 gd_net 不加入依赖。B 站 WBI 使用参考实现中的纯 MD5 算法，YouTube 客户端后备版本参考 yt-dlp 官方当前配置，优先从官网 ytcfg 动态读取。

在线源枚举保留网易云=0、QQ=1、酷我=2，新增 YouTube=3、B 站=4，本地=5。网络源数量不包含本地，发现页仍只支持既有三家；持久化兼容旧资料库 v1 和队列。文件夹歌单只记录规范路径、扫描选项和文件曲目，不复制音频；扫描在后台完成，失败或清除后过时结果不覆盖已有资料。AAC/Ogg/Opus/WebM 交给可选系统 FFmpeg，转码输出显式位于应用缓存，缓存清理识别新增格式。

用户反馈后移除“歌单灌入搜索列表”的旧路径：搜索结果、歌单详情、播放队列各有独立数据。浏览本地、账号或发现页歌单进入含返回按钮的详情页，不改变搜索词、结果或播放队列；点播时才以对应曲目集建立队列。在线请求有独立代际，关闭或打开另一歌单后旧返回不覆盖新详情。收藏更新通过资料库版本同步到已打开的保存歌单视图。搜索换源与歌单换源使用各自的曲目集；搜索点播使用本帧显示的快照，换源按歌曲身份匹配后台结果，避免新结果到达时索引漂移。行高亮也按正在播放的歌曲身份判断，不再跨页面共用选中索引。

YouTube 仅接受明确直链，不能将 signatureCipher 内的 URL 当可播地址；可选 yt-dlp 使用独立 argv、禁用用户配置和缓存，并设置进程超时。Windows 使用 Job 管理工具子进程，Linux 使用独立进程组，超时会终止并回收。未自动安装工具、浏览器扩展或登录依赖。原有 miniaudio 和 libcurl 构建边界不变。

回归重点：旧数据兼容、递归扫描/取消、LRC、路径和队列恢复、缺失文件不联网、清理保留原文件、歌单浏览不改搜索/队列、在线搜索不覆盖歌单/队列、WBI/MD5、YouTube Renderer 与加密格式拒绝、容器头检查及外部工具超时。真实 YouTube 播放仍受本机出口及服务端验证限制，不标为验证通过。

本次 Windows MSVC / MinGW Release 构建和各 5 项 CTest 均通过；补充的后台结果重排、按显示快照点播回归也已在两套编译器通过。真实设备验证 WAV、MP3、FLAC、M4A、Ogg、Opus、WebM 的播放、暂停、定位与自然结束；隔离配置的实际窗口确认文件夹导入、歌单详情、离线播放与在线搜索各自独立，原音乐不被修改。B 站已真实下载并解码完整音轨，酷我样本为试听。审查修复了跨页面共用选中索引和后台结果更新导致点播索引漂移的问题。当前机器没有 Linux 运行环境，本次新增内容尚未重新运行 Linux CI，前述 Linux CI 结果仅指已有版本。
