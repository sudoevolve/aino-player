## 范围与结论

本轮以 `6f21cd0` 为代码基线，盘点自有 C++、平台 JS、Python 工具及文档，重点检查电台、歌词、搜索分页、持久化、音源适配和平台边界。不改第三方库，不新增依赖，不改变资料库格式和正式版本号。静态盘点不等于所有路径的运行验证。

IME 多窗口定时器实验已撤回，`src/aino.hpp` 恢复基线内容。实验用绘制调度列表代替原生窗口清单，不能覆盖未注册绘制回调的窗口，还存在零 timer ID 的误匹配风险；因此没有足够证据保留。此结论来自消息路由审查，不是实机输入验收，也不说明所有 IME 场景均已解决。

历史实验回退提交 `4d8bc4e` 已包含在本地记录的 `origin/master` 中；本轮撤回的是之后遗留的未提交定时器实验，不需要重复创建远端回退提交。

## 已整改问题

| 问题 | 影响与修正 |
| --- | --- |
| `Track::current()` 仅约束索引上界 | 负索引转成 `size_t` 可越界；现在同时约束上下界，空版本列表仍返回空对象 |
| 电台按歌名搜索兜底 | 标题相似不代表风格相似；删除此路径，搜索只定位同一录音，再调用平台相似接口 |
| 电台探索路径跳过真实相似接口 | 空批次后优先跨平台推荐，之后仍可回到原平台；B 站保留自身相关推荐回退，已关闭平台不参与跨平台反查，当前种子的原平台接口仍可使用 |
| 合唱歌手限额不完整 | 最近歌手窗口改为记录每首曲目的所有歌手，未知歌手曲目也推进窗口，过期计数及时删除 |
| 歌词失败后不再自动取词 | 区分有效歌词、加载中、空结果和异常；失败间隔 15 秒重试，同曲最多三轮，手动重试可重置 |
| 补译异常覆盖已有原文 | 异常恢复前检查已经发布的歌词，保留有效原文，只结束加载状态 |
| 歌词跨源仅反查网易云 | 统一平台取词派发，扩展到已启用的五个平台；已有版本优先，候选去重，每个平台最多三个同录音候选 |
| 推荐与取词的检索开关未同步 | 任务快照从 UI 的平台掩码填充，避免始终使用默认网易云 / QQ 开关，确保新启用的平台可参与反查 |
| 推荐种子与歌词的录音判断重复 | `music::matches_recording` 统一校验标题、版本、歌手交集和已知时长差，避免用翻唱或片段替代原曲 |
| 无效分页游标及旧声明 | 删除从未产生实际值的 continuation 字段、参数和一个签名不一致的旧前置声明；保留实际使用的数字页码与 offset |
| 四个无调用旧函数 | 删除 `quality_short`、`wr_be32`、`write_replace` 和整文件内存版 `inject_mp4_tags`；生产 MP4 标签写入继续使用有界流式实现 |
| 自有编译告警和含混命名 | 修正误导缩进、部分聚合初始化、变量遮蔽、平台专用未用参数和字节常量转换；不全局屏蔽告警 |
| 文件接口与环境变量重复适配 | 下载复用 UTF-8 文件接口并声明依赖；Windows 文件打开使用 `_wfopen_s`，音源目录覆盖复用 Unicode 环境变量接口 |
| 开发约定覆盖不全、文档滞后 | 扩展 EditorConfig 到自有源码，排除上游文件；补模块职责、取消与线程约束、静态检查入口，更新实际推荐和取词行为 |

删除函数前已检索自有源码、测试和手动探针的调用关系；单次引用扫描仅作线索。`tools/probe_*.cpp` 仍承担手动诊断职责，没有因不进入主程序而删除。依赖中未确认存在可以安全移除的项，因此没有凭名称删库。

## 设计边界与保留限制

- UI 通过业务动作和 `ViewModel` 访问状态；电台与歌词适配返回结果，由业务层维护队列、取消代次与重试。`Player` 的设备操作保持由 UI 串行调用，后台流与音频回调不直接操作业务队列。
- `business.hpp`、`ui.hpp` 和 `sources.hpp` 仍偏大，业务实现仍由 `cover_decode.cpp` 承载。后续应按独立职责逐步拆出编译单元，避免在本轮缺乏运行验收时整体搬动全局状态。
- 风格相似取决于网易云 / QQ 上游数据；B 站只有相关推荐。其他平台及本地歌曲须能匹配在线种子，没有结果时显示原因并重试，不能保证永远有新曲。
- 歌词默认一轮 24 秒总预算，不能保证慢网络下遍历所有平台；三轮仍失败时需手动重试。翻译只能使用平台提供且通过原文、时间轴校验的内容。
- LX 的 `lyric` / `pic` 消费、AES / RSA、zlib、multipart 和完整 Node API 仍未实现；酷我、酷狗、咪咕的独立歌手 / 专辑目录仍有缺口，详见平台能力表。
- Wayland 原生窗口可构建，桌面托盘、悬浮歌词等 X11 集成仍依赖 XWayland；编译不能证明 WSLg 或具体桌面的全部交互正常。
- 上游 aino / miniaudio 及自有旧编码转换接口仍可能有告警，保留明细，不以禁用告警作为整改。

## 验证记录

本轮只执行必要编译、语法与静态检查。`tests/controller_tests.cpp` 补充索引、录音匹配、合唱计数和取消边界检查，只编译、不执行；发布时再统一运行。

静态盘点覆盖 59 个自有源码文件；Python 使用 AST 解析，不执行脚本。五个 Provider JS 均通过 `node --check`，文件关联静态检查和 Markdown 本地链接检查通过；`git diff --check` 通过。四个删除函数无剩余调用；未发现可确认删除的额外依赖。

最终改动的编译全部通过，退出码均为 0：

| 配置 | 只编译的目标 | 本地日志（忽略文件） |
| --- | --- | --- |
| Windows MSVC Release，嵌入 FFmpeg | `aino_player`、`controller_tests`、`player_tests` | `build/quality-20261124-windows-complete.log` |
| WSL Ubuntu 24.04 / GCC / X11，不嵌入 FFmpeg | `aino_player`、`controller_tests`、`player_tests` | `build/quality-20261124-linux-complete.log` |
| WSL Ubuntu 24.04 / GCC / 原生 Wayland，不嵌入 FFmpeg | `aino_player` | `build/quality-20261124-wayland-complete.log` |

Linux 完整编译剩余告警来自 miniaudio 的未用变量和忽略 `read` 返回值；Windows 剩余告警来自 aino 的变量遮蔽 / 旧 CRT 接口，以及自有代码的 `getenv`、`codecvt` 等弃用接口。没有通过全局静默选项掩盖它们。Linux 主程序曾显式重建两个应用对象，避免头文件依赖未触发时误用旧产物。

自动自审重点核对了取消作用域的恢复、过期 generation 的结果丢弃、歌词失败后的加载状态、先行发布原文的保留、歌手计数淘汰、分页参数删除后的调用关系和空队列补歌。模块职责及依赖方向保持不变，未更改播放音源选择或持久化平台编号。主要残余风险是外部平台数据和缺少本轮运行验证，不能据此认定所有线上场景正常。

上述审查阶段未运行 CTest、音频格式回归、浏览器端到端、窗口交互或整套 CI；也未提交、推送、打包、安装或发布。随后用户明确要求发布 v0.5.5，发布阶段另按完整流程验证；不能将上述编译记录当作发布回归记录。真实平台推荐、歌词网络回退和 IME 实机输入仍需实际使用确认。
