## 方法与边界

同一 Ubuntu 22.04 runner、相同 Release 编译参数、相同精简 FFmpeg、同一份中文歌词与生成的 120 秒音频。关闭 BUILD_TESTING，仅编译 aino_player。两个版本注入同一份诊断钩子，普通播放器入口和 IME 文件没有修改。

Xvfb 下逻辑窗口 1180×760，100% 实际像素为 1180×760，200% 为 2360×1520；使用 PulseAudio 的实时软件输出设备。每组约 50 秒，依次记录空闲、本地 MP3＋歌词、HTTP AAC 流式播放＋歌词、分页访问 160 张 192×192 封面和停止后的内存。HTTP 地址解析使用本地固定地址，后续 HTTP 传输、内置 FFmpeg 管道、三秒环形缓冲、真实音频设备回调、播放器状态与歌词绘制均使用原实现。

每 0.5 秒采样 /proc 状态与 smaps_rollup；记录播放器与所有线程创建的解码子进程，分别汇总 RSS、PSS 和 Private_Clean＋Private_Dirty＋Private_Hugetlb。四组都验证实际播放状态与进度持续推进，AAC 阶段进度从约 0.2 秒推进至约 13.5 秒，封面阶段继续推进至约 30 秒；每组 99～100 个采样。

以下稳态中位数排除每阶段起始两秒；峰值使用该阶段所有采样。阶段边界存在最多一个采样周期的状态切换误差，不将边界峰值当作稳定播放占用。每个组合只运行一次，不据此判断长期泄漏或统计显著性。这是 X11/Xvfb 的受控诊断，未覆盖用户实际 Wayland/XWayland 桌面、系统内存压力、在线音源接口或长期运行。

## 归因与后续方向

- 200% 缩放的旧版封面压力峰值达到 84.29 MiB，与用户反馈的约 86 MB 接近；这表明该量级可以在受控场景出现，但不证明用户场景具有相同归因。
- 12 MiB 封面预算有效，约节约 10 MiB；它没有解决无封面时的常驻占用。
- X11 像素后备缓冲按实际像素大小分配：100% 为 3.42 MiB，200% 为 13.68 MiB，增加 10.26 MiB。实测 AAC 主进程随缩放增加约 10.4 MiB，与这一分配变化相符。
- AAC 阶段 smaps 显示，Noto CJK 常规与粗体字体文件的驻留映射合计约 8.63 MiB，librsvg 本身约 6.15 MiB；字形位图缓存仅约 0.03 MiB（100%）/0.11 MiB（200%）。因此不能继续笼统认定字形缓存导致全部内存差距。
- 下一步应针对 SVG 图标加载依赖、字体文件驻留映射和像素缓冲逐项评估，保留相同图标、字体和歌词显示。此次没有根据这些数字盲改加载器或卸载仍在使用的动态库。
- Windows 没有在本次 Actions 中运行，不能将这些 RSS 数字直接作为与 Windows 私有内存的等口径差值。

### 相同场景结果

以下使用 AAC 稳定播放阶段中位数，单位 MiB。Linux RSS 与 Windows Working Set 都统计主进程驻留页；子进程树的值为各进程 RSS/Working Set 之和，包含共享页重复计数，不等于系统唯一物理内存。

| 缩放 | 项目 | Linux | Windows |
|---|---|---:|---:|
| 100% | 播放器主进程 RSS / Working Set | 49.20 | 32.72 |
| 100% | FFmpeg RSS / Working Set | 5.90 | 9.98 |
| 100% | FFmpeg 的 conhost.exe | 无 | 6.79 |
| 100% | 主进程＋完整解码子进程树 | 55.10 | 49.49 |
| 200% | 播放器主进程 RSS / Working Set | 59.49 | 44.81 |
| 200% | FFmpeg RSS / Working Set | 5.89 | 9.96 |
| 200% | FFmpeg 的 conhost.exe | 无 | 6.79 |
| 200% | 主进程＋完整解码子进程树 | 65.38 | 61.57 |

Windows 子进程逐一保存文件名、PID、内存和创建时间，确认主进程外的占用来自临时目录中的 ffmpeg-1f7e52222bf9823d.exe 及 C:\Windows\system32\conhost.exe。创建时间过滤排除过期父 PID 被复用造成的错误归属；不能采用之前未进行该过滤的 Windows 子进程总数。该实验中 Windows 的解码进程树比 Linux 大约 10.9 MiB，所以漏算 FFmpeg 不仅低估 Linux，也低估 Windows。

200% 封面压力阶段，优化版 Linux 主进程峰值为 72.52 MiB，Windows 为 59.47 MiB；完整进程树峰值分别 78.48 / 76.23 MiB。两者封面缓存持有的 RGBA 均为约 11.95 MiB。不能把这组结果与旧版 22.5 MiB 封面缓存的 84.29 MiB RSS、或用户截图中的私有提交列直接混为同口径对比。

Windows PrivateUsage（私有提交）在 AAC 阶段分别为 8.10 / 18.27 MiB，而 Working Set 为 32.72 / 44.81 MiB。Linux Private_Clean＋Private_Dirty 是驻留页分类，Windows QueryWorkingSet 的 Shared=0 表示不可共享驻留页，两种私有页规则也不完全相同；本报告不把它们或 PrivateUsage 当作同一个指标。定义对照 Microsoft PROCESS_MEMORY_COUNTERS_EX、PSAPI_WORKING_SET_BLOCK 和 Linux kernel proc 文档。

### 实现原因与量化证据

**系统窗口与实际绘制不是同一层。** Linux 后端创建 X11 窗口，几何与图像绘入客户端 RGBA 后备缓冲；X11TextRenderer 使用 FT_Load_Glyph 光栅化并将字形混合到客户端像素，最终由 XPutImage 上屏。Windows 文字使用 GDI ExtTextOutW，图标使用 Segoe Fluent Icons/MDL2 的 GetGlyphOutlineW。Linux 使用系统安装的 FreeType、fontconfig、GdkPixbuf、librsvg，不代表这些代码和字体文件的内存由 X Server 代为承担。Windows 和 Linux 的几何绘制同样都有客户端缓冲，不能说 Windows 完全没有像素缓冲。

**图标加载链路是已量化的主要额外成本。** Linux 系统图标路径从桌面主题选取 symbolic/scalable SVG，通过 GdkPixbuf loader 在播放器进程内加载 librsvg 及其依赖。对同一诊断二进制，仅在临时诊断钩子中跳过系统图标加载，100% AAC 主进程 RSS 从 49.20 降到 38.81 MiB，减少 10.39 MiB；完整进程树从 55.10 降到 44.70 MiB。映射差值主要为 librsvg 6.38 MiB、libxml2 0.92、Cairo 0.64、ICU 0.59、Pixman 0.44，以及 Pango/Harfbuzz 等小项和动态分配。这些依赖的归属可能共享，差值才是该实验的净影响。图标屏蔽改变诊断画面，仅用于归因，绝不作为产品的内存优化成果或去除系统图标的授权。

**字体文件驻留与字形缓存应分开。** Linux 播放阶段字体文件映射约 9.2 MiB，其中 CJK 常规与粗体约 8.6 MiB；字形位图仅 0.03 / 0.11 MiB。Linux 明确在进程内通过 FreeType 打开并持有这些文件，Windows 则通过 GDI 请求字体绘制。该结构及 Linux 文件映射解释了额外字体资源的来源；没有执行删除中文字体或改变字体的实验，因此不能把全部 9.2 MiB 当作已经精确证明的跨系统净差值。

**DPI 缓冲是双方共同成本。** 两边相同尺寸均分配约 3.42 / 13.68 MiB 像素缓冲，Windows VirtualQuery 确认 DIB 为 MEM_PRIVATE（131072）。因此此前“200% 缓冲增加约 10.3 MiB”的计算正确，但它不是 Linux 独有的跨平台缺陷，不能将这部分全部计入 Linux 相对 Windows 的差值。

**封面缓存策略属于播放器，图标/文字路径属于 aino 后端。** 旧版大量浏览封面能积累 22.5 MiB 像素，该项预算优化对两边都适用。Linux 主进程额外占用的下一步优化重点应是保留系统主题图标效果的加载实现，以及字体资源持有方式；不能通过隐藏图标、替换中文字体、降低 DPI 或减少歌词效果制造改善。流式 PCM 环形缓冲两边都是三秒、48 kHz、双声道 16 位，约 0.55 MiB，不足以解释十几至几十 MiB 的主进程差异。

上述诊断只推送独立分支；没有发布、没有推送 master 或 aino 上游，没有执行完整回归。结果说明主要成本来源，未声称每个系统的全部页面都已一一配平，也未证明长期运行不存在其他内存问题。

### 实现、画面和边界

图标仍使用原系统主题 SVG/PNG、原解码器，短时子进程只输出最终 alpha。应用在窗口、音频和业务初始化前调用 `system_icon_worker_entry(argc, argv)`；未接入的应用保持原加载行为，其他平台返回 -1。posix_spawn 复用当前可执行文件，无新增包依赖，失败回退原解码，保留图标。

缓存目录 `$XDG_CACHE_HOME/aino-system-icons-v1`，默认 `~/.cache/aino-system-icons-v1`，预算 8 MiB，可删除重建。键包含源路径、大小、纳秒修改时间、目标尺寸及协议版本；检查所有者、类型、长度和尺寸，临时文件写入后原子 rename。字体覆盖表按文件/index 共享；十秒未参与新字形生成的 FreeType face 可释放，已有字形和 metrics 保留，缺字时按同文件/index/字号重开。
